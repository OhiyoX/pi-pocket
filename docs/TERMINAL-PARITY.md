# 与 pi 终端（TUI）显示逻辑对照

> 取证方式：在 host-a 上用 `tmux` 跑真实 `pi`，让模型触发 bash 工具，然后 `tmux capture-pane -p -e`
> 抓带 ANSI 的屏，把 SGR 码解开读 RGB。**下表是对实测值的记录，不是推测。**

## 一、颜色（dark，实测 RGB）

| 元素 | 终端实测 | 说明 |
| --- | --- | --- |
| 正文 | `rgb(222,224,225)` | 近白 |
| **用户消息块** | **背景 `rgb(33,59,73)` 深蓝** + 前景 `rgb(222,224,225)` | **有底色**！（首轮取证只 grep 了文本行，漏了单独一行的 `48;2` 码，已更正） |
| **thinking** | `rgb(150,160,164)` + **斜体**（SGR `3m`） | 灰、斜体，**不是绿色** |
| 行内 code / 路径高亮 | `rgb(167,152,215)` | 紫 |
| **工具块背景** | `48;2;37;65;49` = `rgb(37,65,49)` | **深绿底**，成功与失败**都用这个绿底** |
| 工具命令 | 粗体 + `rgb(222,224,225)` | |
| 工具元信息 `(yield 3.0s · cwd: ~)` | `rgb(157,165,169)` | 灰 |
| 工具输出 | `rgb(157,165,169)` | 灰 |
| 耗时行 `took 0.0s · exit_code=… · log: …` | 灰 `157,165,169`，其中 **`exit_code=N`（≠0）标红 `rgb(234,127,129)`** | |
| 错误提示行（如 `Error: Request timed out.`） | `rgb(234,127,129)` | 红字、无底 |
| 分隔线 / 边框 | `rgb(151,118,229)` | 紫 |
| 状态栏 / footer | `rgb(126,136,142)` | 灰 |

**结论（回答「tool call 什么时候灰什么时候绿」）**：
- **绿 = 工具块的背景**（只要执行了命令/工具，无论成功失败都是深绿底）；
- **灰 = 工具的参数、输出、耗时这类元信息**；
- **红 = 失败的那一小段**（`exit_code≠0` 本身、错误消息），不是整块变红。

## 二、结构逻辑

1. **thinking 不折叠**：默认整段显示（斜体灰）。实测一次回复里 4 段 thinking 全部可见。
2. **工具块三段式**：`$ 命令 (yield Ns · cwd: …)` → 输出 → `took Xs · exit_code=… · log: …`，整块深绿底。
3. **失败不换底色**，只在耗时行里把 `exit_code=N` 标红；错误消息另起一行红字。
4. **每轮结束一条紫色分隔线**。
5. **用户消息是深蓝底块**（不是无底色）。

## 二·补：输入框与 footer（2026-10-18 实测口径）

- **斜杠命令补全**：输入框以 `/` 开头时列出命令候选（名字 primary + 说明灰，最多 6 条），点一条填进输入框。
  **必须归一化全角 `／`**（U+FF0F）—— 中文输入法常打出全角，否则永远不出候选（实测踩到）。
  输入区左侧还有个 **`/` 按钮**（传图右边、**远离发送键**避免误触）：点它进入**命令模式**（按钮变 filled 高亮态），
  **输入框内不再塞多余的 `/`**，候选按当前文字**实时过滤**（前缀优先 → 包含命令名 → 包含说明），
  **全部命中都列出来**（可滚动，上限 50，底部显示“共 N 个匹配”，不再只 take(6)）；
  候选区必须有**实心底**（surfaceContainer），否则会和上面对话文字重影；slash 按钮用 **inlineCode 紫**（不是 primary 蓝）。
  桥没返回命令清单时用内置兜底（/help /model /mode /compact /new …）。
  选中候选后把 `/xxx ` 填进输入框；再点按钮退出命令模式。
  进入命令模式会**自动把焦点交回输入框**（否则第一次能过滤、接着打字没反应 —— 实测踩到）。
  发送时若仍在命令模式，会自动补上 `/` 前缀。
- **扩展状态（setStatus）**：终端里在 footer，app 里也压在输入区上方一行小字（`labelSmall` + footer 灰），
  不再占据对话顶部一大行（用户反馈「排版有点乱」）。
- **标题栏**：主标题=会话名（无则用会话 id），副标题=**短模型名**（去 provider 前缀）+ 思考等级 + 上下文%，
  不再把 `auto-provider/deepseek-…` 整串塞进去被截断。
- **工具行折叠**：参数摘要清掉换行并截 60 字（MCP 的 JSON 参数常带 `\n`）；折叠态只留**尾部 2 行**；
  **只有 header 行可点**（展开后点内容是选中文本，不会误触收起）。

## 三、扩展交互请求（select / confirm / input / editor）

pi 的 `docs/rpc-extension-ui.md` 定的协议，app 已实现并能应答：

| method | app 表现 | 应答 |
| --- | --- | --- |
| `select` | 标题 + 选项列表 | `{value: 选项}` |
| `confirm` | 标题 + message + 确定/取消 | `{confirmed: bool}` |
| `input` | 单行输入框 | `{value: text}` |
| `editor` | 多行输入框（带 prefill） | `{value: text}` |
| 关闭 | 取消 | `{cancelled: true}` |

带 `timeout` 的请求会提示「不回应 pi 会自动继续」（真实兜底在 pi 侧）。
**不用模态弹窗**，但**用标准 M3 样式**（用户最终口径）：会话页里就地加载在**输入区上方**（`PendingPromptSection`）——
`Card`(surfaceContainerHigh, shapes.large) + `titleMedium` 标题 + `IconButton` 关闭 + 选项用 `ListItem` 逐行点选 +
`FilledTonalButton`/`TextButton` 动作 + `OutlinedTextField` 输入；
会话列表 / Shell 页只放一条非模态提示条（`PendingPromptBanner`，可「去回应」或「开新会话」）。

**端到端验证（2026-10-18）**：host-a 上隔离环境（`HOME=/tmp/uitest-home`，端口 8790，不碰默认环境）跑一个只调用
`ctx.ui.select/confirm/input` 的临时扩展；app 弹窗 → 点选 `beta` → 点「确定」→ 输入并「提交」，
临时扩展实际收到 `select=beta / confirm=true / input=<输入值>`。另用脚本直接驱动 RPC 也验了一遍协议格式。

### 表格为什么不用字形画框

先把终端口径的 `┌─┬─┐` 字形表实现了，结果**中文表头那几列相对 ASCII 行漂约 20px**：
安卓的等宽字体对 CJK 的实际 advance 不是 ASCII 的整数倍（终端靠 `wcwidth`，字体不保证）。

Termux 的做法（一手读源，`termux/termux-app@master`）：

- `terminal-view/.../TerminalRenderer.java`：构造时量一次 `mFontWidth = paint.measureText("X")`；
  画的时候 **x 坐标 = 列号 × mFontWidth**（不是量字符串），每段文本宽度 = 列数 × mFontWidth。
- 每个码点按 `WcWidth.width(codePoint)` 占 1 或 2 格；若**实测宽度 / mFontWidth 与 wcwidth 差 >0.01 格**，
  就 `canvas.scale(runWidthColumns / mes, 1f)` 把这段**横向拉伸/压缩**到刚好占满格子。
- 同风格、同选择/光标状态的连续格子归成一段（`drawTextRun`），颜色走调色板 + SGR 效果位（粗/斜/下划线/暗/反显）。

⇒ 终端能对齐不是字体好，而是**它强制格子网格 + 必要时缩放到格子**。app 侧等价做法：
列宽用 `TextMeasurer` 实测（不猜格子），线用 Compose 画（方角、1dp、`TerminalColors.muted()`）；
列表/代码块仍按终端口径缩进。**未做**：按 `wcwidth` 把 CJK 缩放到整数格（Compose 里要按 run 切 `graphicsLayer` 缩放，价值不足）。

### 表格实现里踩到的一个 Compose 坑

外层是 `horizontalScroll`（约束 = 无限宽）时，里面的 `fillMaxWidth()` **会失效**：
`HorizontalDivider` 被压成几像素的“小报头”，表格看起来**没有横线**（用户报过）。
修法：给滚动内容**写死宽度**（= 各列宽之和 + 边框），内部 `fillMaxWidth()` 才有意义。
